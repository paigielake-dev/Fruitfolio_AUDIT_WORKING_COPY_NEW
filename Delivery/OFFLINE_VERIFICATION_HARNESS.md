# Actual offline verification harness

The new CI-only helper attempts controlled external-network isolation on a disposable GitHub-hosted macOS VM. It refuses to operate on a local Mac, another operating system, a self-hosted runner, or a VM with an already active firewall. It first verifies that the approved model origin is reachable, then temporarily blocks outbound traffic while leaving the simulator's loopback communication available. Before and after actual model execution it requires the external origin to be unreachable.

The test launches the actual built app test host and the official bundled MADLAD integration fixtures, strict native FruitfolioAI research-grounding test, and real Ask answer/return UI journey. A failed isolation probe, failed model fixture, or independent restoration watchdog prevents an offline PASS. Exit/interrupt cleanup restores disabled filtering and the standard system rules; an independent eight-minute watchdog also restores connectivity if the test hangs. This infrastructure does not ship in or modify the iOS app.

This is a pending Mac-simulator verification attempt. It does not establish physical-iPhone airplane-mode acceptance or general clinical translation quality. Packet Filter is an administrative test harness here, not an application API; Apple's TN3165 describes that distinction: https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api

The extended visual traversal receives 45 minutes because the original eight-minute harness reached only its first three feature groups despite making progress. The existing traversal's depth/path limits and non-destructive safeguards remain unchanged; completion of exploration is not exhaustive 478-item acceptance. Evidence packaging now permits 32 independently checksummed parts instead of dropping data when eight parts are insufficient.

Run49 also exposed a nondeterministic test fixture: an exact whole-profile comparison used the live clock across a milliseconds-based JSON round trip. The migration test now uses a fixed integral timestamp while retaining the complete equality assertion. No production timestamp codec or medical validation rule was relaxed. All six newly added saved-reference tests actually passed in Run49; its overall unit run still failed on that clock fixture and is recorded as failed.

Actual Run51 passed 514 XCTest executions (513 PASS, one physical-device SKIP, zero failures) and 25 Swift Testing tests. Its offline stage failed before any model inference: the exported artifact contains only the initial `pfctl` status, which reports Disabled. The helper now captures the status-command outcome before parsing the required disabled state and uses the macOS system grep. This is a harness repair pending actual execution, not an offline acceptance claim. Missing status, non-disabled filtering, failed probes, failed native tests or an early watchdog still prevent PASS.
