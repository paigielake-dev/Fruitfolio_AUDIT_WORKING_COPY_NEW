# Official MADLAD variants and current device limits

The approved [Google MADLAD400-3B repository](https://huggingface.co/google/madlad400-3b-mt/tree/main) was inspected on2026-11-02. Its listed quantized variants are Q2_K(~965MB), Q3_K(~1.26GB) and Q4_K(~1.65GB), alongside an~11.8GB safetensors file. It does not list an official Q8 variant. Smaller official variants are not evidence of improved medical translation quality; none was silently substituted. Requantizing or using an alternative runtime would need exact integrity, architecture, output, memory and safety verification before integration.

The active model remains the original official Q4_K,1,654,597,280bytes, SHA-256 ea6e5531a3e95213c7f0635988d119e078a655c09306e47851e15d4c0c3f9c37. The architecture is T5 encoder–decoder, not a decoder-only chat model. The actual linked Candle0.11.1 quantized_t5 adapter uses official config/tokenizer values: decoder start0, pad1, EOS2; changing them to other T5 defaults is not an approved repair. Existing FruitfolioAI research retrieval and strict generation validation remain separate.

Actual Run97 controlled-offline official-runtime core fixture:34.900310seconds for its bounded Spanish warning/measurement/French uncertainty sequence; process peak Darwin RSS2,155,249,664bytes; reported host physical memory7,516,192,768bytes; inference off main thread. Original observation: `Fruitfolio_Verification_Evidence/AppleRuns/Run97/Offline/core/Attachments/9B271E45-5D54-4167-B765-007F2F167E95.txt`. These are simulator/process observations. They do not establish physical iPhone memory ceilings, Jetsam behavior, thermal performance, battery consumption, concurrency budgets or an acceptable user wait on every supported device.

The existing framework includes arm64 iOS and arm64 Simulator slices. Intel simulator support and physical-device acceptance remain unverified. The weights, tokenizer/config files, FruitfolioAI model and required frameworks materially increase download/storage size; final distribution and device memory/performance acceptance require their own checks. Model presence, a successful build, tokenizer recognition and limited translation fixtures are distinct acceptance states.

The fifteen-language medical fixture actually exercised all requested expanded targets:14quantity/citation preservation passes and one Aymara inference failure. Passing preservation does not verify medication warning meaning, diagnosis negation, language identity or clinical terminology. Earlier raw wrong-language/script outputs and mixed Japanese are retained. Five exact tokenizer targets remain absent(tpi,ty,rar,niu,gil), with no silent alias or substitution. The current Swift diagnostic repair preserves the underlying runtime error instead of reporting only a generic inference failure. No non-EOS partial output is accepted.
