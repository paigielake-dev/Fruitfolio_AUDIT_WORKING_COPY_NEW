# Follow-up to actual Run46 simulator diagnostics

- **Personal Health Context:** The destination opened, but its category elements were exposed as `Other` rather than `Button` because the custom accessibility element lacked the button trait. The new UI regression correctly refused to proceed. The category actions now explicitly retain their native button trait; the test continues to require actual Buttons and the full save/restart/remove journey.
- **Username editing:** A delayed publication from the validated shared username store could overwrite an actively edited draft. After deleting below the three-character minimum, a previous valid prefix could reappear (`berpeach_qa34` instead of `peach_qa34`). External store echoes now update the editor only while it is unfocused; valid local edits still synchronize through the same persistent authority. The ordinary-typing UI test additionally checks that deleting all characters leaves an empty draft.
- **Chinese target tags:** Inspection of the exact official tokenizer found a distinct `<2zh_Hant>` token. A generic two/three-letter Swift target gate could not accept that script target. Required selections now map Simplified Chinese to `zh` and Traditional Chinese to `zh_Hant`; the C ABI still requires the exact token to exist. The runtime syntax gate accepts canonical script suffixes, not arbitrary prompt text. A new actual inference fixture compares script-specific Chinese characters, and a bundled-tokenizer inventory test documents all required selections. Five exact targets remain absent: `tpi`, `ty`, `rar`, `niu`, `gil`; no language aliases or replacement models have been invented.

These follow-ups require their own actual Xcode/simulator results. No new PASS is inferred from these source changes. Production clinical translation remains gated.
