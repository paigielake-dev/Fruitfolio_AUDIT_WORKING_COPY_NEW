# Saved reference preservation

Inspection found that the Ask-to-Library bridge retained source IDs and versions but discarded the original APA reference text. Library and Guide reading surfaces then displayed raw source IDs. This follow-up preserves the original `AskSourceRecord` metadata with full-answer and excerpt saves, carries it unchanged into Guide copies and local persistence, and renders the original reference text in both reading surfaces.

Unreferenced extra metadata cannot acquire attribution. Missing, duplicate, blank or mismatched-version snapshots fail closed. Legacy pages are never silently assigned current references: recovery requires the exact saved library content version, exact source content version, actual source identity and approved-display status. Otherwise the original saved answer remains intact and its reference is explicitly unavailable. Excerpts label the references as belonging to the original answer. Only approved HTTP(S) source links are actionable; no local/custom scheme link is exposed.

Six new unit tests cover exact snapshot preservation, extra-source exclusion, fail-closed metadata handling, safe legacy recovery, Guide-copy/restart preservation and source URL handling. A new actual Ask journey generates an answer, saves it into a uniquely named book, restarts and compares the displayed reference with the original bundled document citation. These changes await actual Xcode compilation and execution. They do not change the strict generated-claim validator, bibliographic metadata, original research text, original saved prose, source IDs or numbers.
