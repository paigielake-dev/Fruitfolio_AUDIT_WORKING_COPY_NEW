# Encyclopedia contents localization

The existing split-book view now translates fixed controls, placeholder/empty copy, page-type descriptions, and book-page accessibility labels through the control translation owner. The physical left/right accessibility descriptions follow the actual environment layout direction. Chapter count glyphs use the selected language's native number locale without inference. Chapter expansion has a translated accessibility value and stable identity.

Book names, chapter names and nonempty saved questions are verbatim. Their wording is never classified as app copy by string equality; even the default chapter name remains verbatim because legacy data has no authored/default provenance flag. Only an actually empty question uses the controlled saved-page fallback. The heart in the original empty-book copy is protected. Source records, citations, bodies, counts in storage, artwork, canonical stores and the two-page architecture are unchanged.

The heading reserves separate space for Back artwork and retains its original font size. Seven new English source fallback records were added, and the three previously empty `complete saved answer`, `expanded` and `collapsed` catalog records received English source values. Four actual Apple UI vectors were written for English/Arabic, inference paused and Reduce Motion at accessibility XXXL. They exercise header separation, physical page accessibility labels, original authored row wording, native count glyphs, chapter collapse/expand, minimum controls and selection/background accessibility isolation.

Apple tests are NOT_RUN. Linux full regressions and source checks recorded in the run log do not prove SwiftUI layout/typechecking, actual translated layout, VoiceOver, model quality or device behavior. No inference or scientific-meaning acceptance is inferred from English fallback tests. No mirrored tests were added for Foundation's built-in numeric formatter; existing genuine persistence/fixture/provenance regressions still execute.
