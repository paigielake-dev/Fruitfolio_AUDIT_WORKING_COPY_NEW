# Scientific illustration source and responsive layout

A shared production aspect-fit policy now sizes full source canvases against proposed width/height and explicit maximum bounds. The SwiftUI Layout uses that exact policy for both measurement and placement. It never crops, stretches, substitutes art, or separately remaps source anatomy. Missing artwork is explicit. Body Biology hero plates, Fertilization primary illustrations, Pregnancy reference plates and explicitly saved science illustrations use the shared renderer. Source files, assets, catalogs and research bytes are preserved.

Scientific images are noninteractive and cannot intercept adjacent explanation controls. Fimbriae explanation is below its image so narrow widths/large text do not squeeze text beside a fixed-width plate. The existing oocyte overlay offsets and dimensions now scale together with the source plate width, retaining their nominal relationship rather than extending a fixed offset beyond narrow viewports. These inherited anatomical offsets/menstruation annotations are **not clinically or visually validated by this batch**; source review remains necessary before asserting anatomical registration accuracy.

Body Biology prose now uses the existing semantic/translation renderer in serious mode, with an explicit general-reference/uncertainty notice. Existing Pregnancy translated research prose also uses serious semantic mode. No new medical measurements, inference, diagnosis, supporting evidence or citations are fabricated. Translation still depends on approved local assets; official MADLAD weights/tokenizer remain externally blocked. No translated runtime output is claimed.

Reduce Motion is rechecked after the oocyte delay and resets any existing displacement without animation when activated. Apple runtime is required to verify the cancellation race visually, custom Layout typechecking, source-image registration, Dynamic Type, VoiceOver and hit testing. Linux compiler parsing and six pure production-sizing regressions establish bounded aspect-preserving geometry only.

Body Biology production routing now consumes the typed Today context, not title-string matching. The current Today contract supplies no typed ovulation/luteal/follicular phase, so cycle-day numbers or translated prose cannot invent those personalized states. The legacy title mapper remains compatibility-only. Day-one character confirmation also requires a recorded bleeding observation. Existing presentation tests plus typed routing regressions exercise this boundary; the older onboarding-current-period freshness question remains a separate Today data-provenance issue to resolve next.
