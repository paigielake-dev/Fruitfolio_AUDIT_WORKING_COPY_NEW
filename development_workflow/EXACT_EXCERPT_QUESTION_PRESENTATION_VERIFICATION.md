# Exact-excerpt question framing

The known source-excerpt template now separates its fixed instruction from the literal cloze. The generator uses shared constants whose values match the prior category/prefix exactly; stored question text, original excerpt, choices, correct-answer identity, explanations and citation metadata are not migrated or rewritten. A read-only UTF-8 prefix split preserves literal excerpt bytes, including operators, identifiers, combining marks and whitespace. Unknown/legacy/empty templates fall back to the complete original question text.

The fixed instruction and explicit source-language notice use the existing catalog/MADLAD display pipeline. The quoted cloze uses the shared semantic renderer with explicit plain spans, and exact answer words remain verbatim: translating those words independently would change this source-word-matching exercise. This is a framing change for the existing excerpt practice, not a new translated clinical concept bank or an inference exclusion. Existing explanation translation and original-source storage remain. A separate reviewed conceptual question bank remains unavailable as documented.

The question flow now scrolls, allowing long excerpts and large Dynamic Type choices to remain reachable. Two Foundation regressions test literal byte preservation, original saved-question/source identity and unknown-template fallback. Four Apple UI scenarios use a clearly synthetic excerpt, English/Arabic app settings, maximum text and both motion settings; they check original quote/choice labels, scrolling and the actual correct-answer transition. They explicitly pause inference to exercise honest source/catalog fallback and remain NOT_RUN without Apple SDK. Parser success does not establish SwiftUI typechecking, clipping, actual RTL/VoiceOver or physical sound.

Two English-only catalog keys bring the catalog to 677 entries, preserving all prior 675. No foreign translations are added or marked reviewed. Official MADLAD weights, linguistic/clinical and device verification remain blocked. Final feasible results are recorded in the batch log.
