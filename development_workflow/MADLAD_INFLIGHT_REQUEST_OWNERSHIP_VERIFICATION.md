# In-flight translation ownership and bounded sharing

The production translation service now coalesces simultaneously active identical machine requests. Catalog lookup and source-language bypass still happen first, and paused callers cannot join inference. Sharing keys preserve source UTF-8 bytes, target tag, source language bytes and the exact explicit-protection context. Random scientific placeholders and restoration/validation belong to the shared operation; only its validated complete result can reach callers.

Each caller owns a waiter. Cancelling one caller does not cancel another owner's work. Cancelling the last owner cancels and removes that operation. Generation identities prevent a stale completion/cancellation from removing a newly started same-source operation. Resource release cancels/removes shared operations before forwarding native release. Native C calls remain synchronous and non-preemptible.

Sharing metadata is bounded to 32 distinct requests and 64 waiters each; eligible source is at most 16 KiB UTF-8, source-language metadata 64 bytes, and at most 64 explicit literals totalling 4 KiB. Overflow uses the original caller-owned uncached path, without truncation/rejection. These are sharing-metadata bounds, not a resident-memory guarantee. Overflow work retains the existing caller-cancellation/native-serialization behavior; resource release does not gain ownership of every possible overflow caller. There is no completed-result or failure cache, no disk cache, and no retained source-key entry after the final owner completes. View-owned accepted displays retain their existing behavior.

Nine Foundation scheduling regressions cover deduplication plus original scientific protection, no completed cache, individual/last cancellation, stale completion/new-generation ownership, rejected output retry, byte-distinct Unicode, target/source/protection distinctions, memory-paused callers and all sharing bounds. Their identity protocol fixture is explicitly not native or translation output.

A separate actual native T5 regression gates entry to the real production actor (no C API replacement), starts eight owners and requires one actual encoder/two decoder calls with a complete synthetic fixed-token result. It then retains loaded native resources while two new owners wait, releases the service, requires native resources to clear and queued shared work to cancel without reloading, and checks a fresh request genuinely reloads and decodes. The gate controls scheduling only; all successful output comes from the actual untrained T5 graph. No official MADLAD, clinical translation, device performance, total memory or leak guarantee is implied.

Final feasible results are recorded in the batch log. Official model/Apple/clinical gates remain blocked as documented separately.
