# Moving game object accessibility localization

Moving fruit and standalone-star labels now use one image-only accessibility translation modifier backed by the genuine shared control translation state. Complete fruit/belonging descriptions keep the game distinction intact; the standalone bonus star remains a separate “star pass.” Translation keys contain fixed copy/language, never coordinates, rotations, elapsed time or counts. Plain semantic text prevents exposing emphasis markup to VoiceOver, and the status hint reports original/preparing/unavailable or machine provenance.

Classification supplies its existing complete fruit/marker/question description directly to this same owner. This replaces the prior outer generic translation wrapper and inner default English label, avoiding two independent translation states for one image. Image-only fallback status now resides in the accessibility hint; the separate on-screen translated question retains its visible status/original controls. No new visible translations or quality claims are fabricated.

Twenty English-only complete fruit/belonging entries preserve all 765 previous catalog entries; “star pass” already existed. Fruit rendering, attached markers, star art, source/medical data, gestures and collision geometry remain unchanged. Catch objects now have distinct QA identifiers.

The new private catch-object fixture seeds actual render records and holds the real frame-advance guard. Four Apple UI launches cover English/Arabic and motion settings at accessibility text size, requiring distinct good/bad/standalone labels and no raw markup. They are NOT_RUN without Apple SDK/runtime and do not prove live object performance, audibility, VoiceOver traversal or physical collision behavior. Existing classification cases continue exercising the complete marker/question description. Feasible full Foundation/native/workflow/parser results are recorded separately and do not substitute for runtime verification.
