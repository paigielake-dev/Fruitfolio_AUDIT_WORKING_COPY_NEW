# Batch evidence contract

Every implementation batch continues to target original source-order IDs in `requirements` (1–478). Add exact separate founder IDs in `supplemental_requirements` when applicable, for example `SPEC-7.9.6` or `SPEC-BINDING-ASK-SESSION`. They never replace or renumber the original checklist. The separate index contains 24 numbered additions plus 12 explicit bindings; it does not claim to index every unnumbered founder paragraph.

Use `entry_evidence` for original-row-specific evidence and `supplemental_entry_evidence` for founder-row-specific evidence. Each override supplies `summary`, `files`, `tests`, and `verification` with `executed` results, `not_run` tests, and `remaining` acceptance requirements. Without an override, the row receives the batch evidence. Record only actual execution; source, synthetic T5 and Apple/official-model acceptance remain separate.

`Tools/record_prompt1b_batch.py` validates targeted IDs, exact founder text/hash/order against the source parser, and recovery-record shapes before publishing. Invalid IDs, altered identities, malformed/unscoped evidence and repeated batch names fail without advancing records. Blocked original and founder statuses remain blocked while component evidence can accumulate. The recorder never promotes whole requirements to complete. Founder rows retain structured `batch_evidence`, latest verification, explicit remaining requirements, source/test references and commit linkage. Checkpoints and run logs retain the two distinct sets of IDs.

`Tools/sync_supplemental_spec.py --check` verifies exact founder source identity. Regeneration preserves known and unknown non-source progress fields, nested values and top-level metadata. `--root` permits isolated fixture verification; normal operation uses this checkout. Source identity fields regenerate only from the preserved founder source data. Historical attachment workflow/model exclusions remain superseded by the current user authorization.

`SUPPLEMENTAL_BATCH_EVIDENCE_RECONCILIATION.json` explicitly maps fourteen recent local batches to twelve founder entries. Each was checked against its committed run log, containing implementation log, commit and hashes. It is a targeted evidence reconciliation, not an exhaustive historical audit or a completion percentage. Source descriptions, original statuses and blockers were preserved. Older unmapped evidence remains available in Git/run logs and must not be inferred complete.

The recorder validates known input/recovery failures before writing, and each JSON publication uses a temporary file replacement. This is not a cross-file crash-atomic transaction or off-machine backup guarantee. Commit coherent batches and verify a unique recovery bundle after the tree is clean. Never push or merge without authorization.
