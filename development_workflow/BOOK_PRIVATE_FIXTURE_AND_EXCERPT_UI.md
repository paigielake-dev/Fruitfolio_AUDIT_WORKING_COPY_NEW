# Private Book regression authority and excerpt UI coverage

The DEBUG Book route now consumes `FruitfolioRegressionPreferenceSuite` from the real root shell, matching the existing Ask fixture ownership. It no longer creates a secondary random suite, falls back to standard preferences, or deletes a preference domain on view disappearance. The root owns suite cleanup. A StateObject retains the Foundation fixture; an observed canonical store drives the real Library and Guide Builder views.

`Prompt10BookRegressionFixture` seeds real canonical-store records only when its private storage key is absent. Existing bytes, explicitly emptied libraries, wrong-type/corrupt/future protected data and user edits are not replaced. Missing private preferences produce no store. Initial empty fixtures acknowledge an empty record through the canonical store. Fixture book creation is not claimed to be an all-or-nothing transaction; errors surface without repair.

The original normal, draft and empty fixture options remain. Two explicit options create a legacy excerpt with a recorded selection, or an ambiguous record without one. These records deliberately retain a synthetic remainder until the actual consent flow runs; simply loading or remounting does not clean them.

Four genuine Foundation fixture tests exercise missing authority, draft/remount/explicit-empty preservation, protected private data and legacy/missing-selection modes. The run log records full-suite and focused execution separately. Six Apple UI vectors were written: four combinations of Arabic/English and Reduce Motion at accessibility XXXL exercise keep-everything, actual cleanup, background accessibility isolation, notes and page remount; two Arabic ambiguous-record vectors verify the unavailable cleanup action. Apple UI tests are NOT_RUN on Linux. Source parsing is not SDK typechecking, focus/RTL/VoiceOver verification or runtime acceptance. Root-owned in-process persistence does not establish process-restart acceptance.
