# Captured Guide reorder ownership

Actual Guide section/page reorder callbacks now carry a `Prompt11GuideReorderOwner` containing the rendered Guide, ordered IDs, language and visit epoch. The root rotates its epoch on appearance/disappearance, scene phase, selected Guide, language, form and read-mode transitions. Live context also checks UIKit application activity and excludes forms/read mode. Native page menus change identity with the epoch so cached presentations can be discarded.

Both callbacks route through real Foundation store gateways before writing. A stale/inactive/hidden/wrong-Guide/language/scope/order request returns false without a setter call, cue or saved-status entry. Missing/duplicate identities and mismatched chapter ownership reject rather than repairing data. Successful requests use the existing canonical move and write acknowledgement. Independent note/image changes do not invalidate placement ownership and remain in the actual latest stored page. An accepted reorder invalidates replay of its prior ordered snapshot.

Capture happens once for the section list and once per page list, sharing immutable arrays across rows instead of sorting/capturing a whole list per page. This is a source structure change, not an RSS or device performance measurement. Fixed section rename/up/down labels now translate and retain their original fonts with a 44-point label target.

Three real-store regressions use genuine private UserDefaults with setter counting. They cover rejected context/scope requests with zero writes, independent UTF-8 notes/source/image preservation, acknowledged movement/remount, stale-order replay, external section movement, duplicate Guide records and ambiguous chapter identities. The initial focused three tests and both initial full suites passed; final full suites cover shared snapshot capture and the section-boundary initializer.

A read-only preference from the actual Guide root exposes its epoch in the DEBUG fixture; the test waits for a changed epoch after background/activation, verifies unchanged fixture ownership/bytes and zero writes, then performs one fresh acknowledged move.
