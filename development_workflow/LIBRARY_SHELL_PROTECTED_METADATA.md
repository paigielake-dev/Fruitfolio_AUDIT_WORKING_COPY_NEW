# Library shell and protected metadata

Six existing Library heading/empty/search/add copy strings now use fixed-copy translation with brand/decorative literals protected. Search uses the existing native fixed-prompt field and canonical clear control, keeping the query binding unchanged. Book names and subtitles remain verbatim; display metadata uses native counts and translated fixed words. Tile titles, subtitles and metadata may grow vertically instead of truncating their reading area.

The new Foundation presentation helper escapes authored fields with the existing plain-span Markdown encoder and supplies them as protected literals to the compact accessibility translation owner. Opening-book labels protect the name the same way. No authored title, subtitle, saved chapter/page or research source is rewritten. Existing secondary text colors are supplied explicitly, including the recently localized dialog/medication notices, to preserve hierarchy.

Three regressions exercise real private-store creation/description acknowledgement plus the actual compact translation owner: selected-locale counts, masked authored input and restored escaped fields, unchanged stored bytes/name/subtitle, rejected dropped identity and protected opening labels. Runtime outputs are deterministic protocol fixtures, not learned translation or official MADLAD/native-language quality evidence.

The existing four Library UI launch vectors now also search for a missing query, use the translated clear control, recover the authored book and check one clear soft-pop request. All four remain NOT_RUN. Actual Apple typography, fully visible long titles, translated metadata wrapping, escaped-name VoiceOver pronunciation, search/clear keyboard behavior and physical audio require Apple/device review.

Initial portable/native builds failed before test execution because the new helper referenced a nonexistent escaping API. This was corrected to the actual shared `FruitfolioSemanticMarkup.markdown` plain-span encoder; compile-failure logs are retained separately from final passing results. Syntax parsing alone never counted as a build pass.

Remaining sort value/expanded-state accessibility copy still needs its own selected-language owner. No whole original397/390/412 requirement is certified, and all official-model/clinical/device blockers remain open.
