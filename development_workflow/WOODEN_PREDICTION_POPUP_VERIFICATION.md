# Shared wooden prediction explanation

The active Tracker explanation now creates an identity-owned woodenSign request
through the existing PopupCoordinator. Its former local two-tint overlay, hard
minimum292pt width, fixed line limits/font shrinking and30pt custom close control
are removed from the active implementation. Navigation/departure cancels only its
owned request. Acknowledgment/Escape use the shared identity guards and modal sounds.
Focus returns through a binding to the actual Today explanation control; that
control uses the canonical small pill and retains the original question-mark art.

The unchanged founder PNG is594x517. Its full alpha bounding box and SHA256 are in
RUN_LOGS/Wooden-popup-artwork-measurement.json. The chosen normalized writing region
is(0.12,0.46,0.76,0.40), visually reviewed on the actual PNG to exclude rope, top
screws and outer edges. It is a design text rectangle, not an automatically inferred
alpha contour. Artwork is neither resized on disk nor background-edited. The shared
layout retains its aspect ratio and fits both viewport dimensions with no fixed
minimum width. Live text/actions scroll inside the board region. The existing Peach
art remains decorative. Compact canonical actions retain the minimum44pt hit area.

Prompt16PredictionLearningInfo moved unchanged into the Foundation model file.
The single production request factory preserves its original title/body/progress
copy; neither the factory nor this migration calculates a new estimate. The shared
host uses its existing translated semantic-text pipeline and request focus/Escape
behavior for both white paper and wood. No official MADLAD inference or semantic
clinical translation acceptance is claimed.

Four new Foundation methods test responsive/invalid viewport geometry and aspect,
original copy/surface selection, repeated/queued/departed close actions, and stale
Escape after replacement. A new workflow test compiles the actual geometry and
compares its metadata to the original PNG/hash using Pillow, including the reviewed
rope/screw/edge exclusion. These are actual production APIs, not mirrored layouts.
The Linux XCTest discovery bridge initially aborted on synchronous MainActor test
entry points; the three actor-isolated test methods now use async entry points.
The initial ambiguous floating test constants also use explicit CGFloat types.
Neither correction changes application behavior to accommodate Linux.

The disposable CycleModalQA scene adds prediction-sign, using the actual factory
and global host with long explicitly nonclinical fixture text. Its added Apple UI
method defines8portrait/landscape xLTR/forcedRTL xmotion-override cases atAXXXL,
checks scroll/action bounds and restores the trigger, and captures screenshots.
This scene verifies request composition/host when run; it does not navigate the
actual Tracker data-loading screen or validate a biological prediction.

Apple SwiftUI/UIKit typechecking, text rendering/scrolling, focus/VoiceOver, Dynamic
Type, reduced-motion visuals and sound playback remain NOT_RUN on Linux. Geometry
and source UI tests are not runtime acceptance. The Mac verification script already
selects the containing UI class, including these scenarios.
