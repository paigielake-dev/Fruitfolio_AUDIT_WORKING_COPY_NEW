# Source-painted Fruit Basket obstacles

Production physics now uses the same original-source-projected frames as rendering. A reproducible build tool reads alpha from the preserved vine, branch and puddle PNGs and bundles 96×96 packed collision masks with source dimensions, painted bounds and SHA256. It never writes an image file. Branch mirroring/placement anchors its thick root to the right playfield edge; vines anchor their actual paint at the left edge. Transparent canvas padding no longer acts as visible material. Required missing/invalid obstacle data prevents a masked round from starting instead of silently inventing geometry.

Wind changes fruit and standalone-star trajectories in code, independently of the animated wind reference. Wind artwork/audio also appear when soft rain includes wind. Particle base fall speed and captured drift remain immutable. Branch paint triggers one short bounded upward bounce and a persistent reflected horizontal trajectory; the old spawn reroll that excluded the branch region is removed. Masked vine contact slows only good fruit and standalone stars, never bad fruit. Contact state drives a small visible strain/wobble and one existing rustle event at entry, rather than replaying audio every frame or slowing items in empty middle-field space.

Soft rain now always includes a puddle, including round combinations that previously had rain with no puddle. Original puddle artwork moves subtly without generated/replacement art; decorative wind/puddle movement stops for pause and Reduce Motion. Basket target-following resists only actual lower-basket contact with painted water, sweeps long drags so they cannot skip the water, continues toward the target after touch events stop, and restores immediate response on dry ground. Its water state is available to accessibility. Basket/puddle ground geometry now remains on screen in short landscape fields; fixed percentage placement previously clipped the basket and placed completion below the viewport. The active field also excludes the reported bottom safe-area inset so its physical ground stays above the home-indicator area.

The specified Strawberry storm note uses the untouched `control_large_card` 634×667 artwork, measured shared writing aperture, shared whole-background modal blur/AX exclusion, exact `uh oh! a little storm is passing. o__o` dialogue, and explicit close/acknowledge controls. It pauses play and appears once per session/round, with no auto-dismiss timer. Large text scrolls inside the source artwork. The shared moving-fruit sprite also restores the missing good-fruit star badge; the instructions previously depended on a marker that was not drawn.

Verification includes actual source alpha/hash reproducibility, sparse paint/transparent padding, middle-field noncontact, mirrored edge contact, painted puddle overlap, coded wind directions, base-speed preservation, good/star versus bad vine behavior, one-time contact/bounce behavior, persistent puddle-target recovery, soft-rain coverage, landscape bounds and large-card source aspect. These are production Foundation algorithms and original asset bytes, not UI mocks. Apple runtime still must verify collision registration visually, badge clarity, convincing bounce/strain/settlement, storm focus/scroll, audio delivery, touch controls, frame rate and physical-device behavior. No iOS typecheck/launch/visual success is claimed on Linux.

Mask generation is build-time only: install the pinned `Tools/requirements-art-analysis.txt` in the setup Python environment when needed, then run `python3 Tools/compile_fruit_basket_masks.py --check`. Regenerate without `--check` after an authorized source-art update, review the JSON and unchanged image-byte history, and rerun regression tests. The app itself has no Pillow/Python dependency. Masks and review metadata are not clinical evidence and contain no user data.
