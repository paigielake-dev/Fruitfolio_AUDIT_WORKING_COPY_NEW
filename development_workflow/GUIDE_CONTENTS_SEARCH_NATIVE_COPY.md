# Guide contents and search copy

Guide contents headings/empty copy and no-match search copy now use the existing control translation owner. Only an actually empty saved question uses the controlled saved-page fallback. Nonempty questions and section names remain verbatim and wrap vertically instead of being limited to one line. The existing search algorithm and six-result preview policy remain unchanged; query text is never supplied as translation prose.

`Prompt11GuideContentsCopy` formats native ordinal/page glyphs without grouping. Ordinals retain a minimum of two digits and never truncate larger values. The accessible description uses an explicit section/page phrase, escaping and protecting the authored section name plus both numeric literals. It does not start with a Markdown ordered-list marker. The view still scrolls to the same canonical section/page IDs; no saved ordering, content, citation, search index or schema is rewritten.

Contents and search-result buttons now use the existing 44-point minimum hit target instead of 38 points, with stable IDs for real Apple verification. Existing artwork, font sizes, animation policy and original operation cues are retained. All four fixed English fallback values already exist and were verified without catalog edits.

One genuine Foundation regression covers padded/nontruncated ordinals, Arabic glyphs, escaped Unicode/clinical-looking authored names and numeric/name protection through the scientific translation envelope across four locales. Initial focused tests passed three cases before the accessible phrase was clarified. Initial full suites passed 968/993 XCTest plus 21 Swift Testing each. Source review then identified the production eight-page search gate; an explicit private search scenario now seeds eight genuine canonical pages before the UI check. A second Foundation regression verifies the gate, derived page positions and refusal to reseed an existing target. Final full-suite results include both changes. Four Apple vectors were written against the private actual Guide fixture for French/Arabic, paused inference, Reduce Motion and accessibility XXXL. They check original section text/native ordinal, 44-point target, unchanged typed search query, no-match feedback, intact persisted bytes and no save requests.

Apple UI vectors are NOT_RUN. Linux tests/parse checks do not execute UIKit scroll targeting, SwiftUI accessible descriptions, VoiceOver/focus, translated layout, actual device touch delivery or official MADLAD/clinical-language acceptance. Search-result long-text layout remains subject to real Apple verification.
