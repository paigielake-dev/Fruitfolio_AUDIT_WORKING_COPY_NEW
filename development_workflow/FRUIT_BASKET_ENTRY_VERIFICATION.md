# Fruit/star entry, settlement and rarity

The previous production collision accepted any object center below normalized y=0.82, above the visible opening for common viewports, and removed/awarded it immediately. The active catch path now uses shared geometry registered to the unchanged 398×380 supplied basket PNG, its bottom alignment and its actual on-screen container width. Crossing the mouth starts a transit; it does not increment score, basket fruit or star passes. Fruit and standalone stars share 0.24s entry and a visible flattened hold before the 0.36s completion event. Only completion applies the existing game-domain consequence. Reduced Motion uses a static settled pose without early awards. Pause freezes frame advancement; large/invalid clock deltas cannot jump transit time unboundedly.

The complete transformed object is below the rim and within the horizontal aperture at settlement. Original full basket artwork stays behind the objects, with an untouched lower source-art overlay forming the front rim/body. No image bytes were edited or generated. Mouth/front-mask registration is an engineering interpretation of the source illustration and remains **visually unverified on iOS**; passing geometry tests is not proof of convincing animation or pixel registration.

The basket now retains the actual successfully caught fruit IDs in order. It previously cycled through the possible good-fruit pool to depict collected content, potentially displaying fruit that was never caught. Stars do not enter that list or count toward 10. The pass bank is visible and star completion uses existing star-chime audio. Completion callbacks are removed after firing once, preserving the final-round lock and delayed Basket Reveal.

All falling fruit, standalone stars and entering objects count toward the configured concurrency ceiling. A star draw is possible only after at least eight intervening fruit drops and then a 5% draw; there is no quota on stars a long round can award or passes a session can bank. Spawn interval is sampled once per spawn rather than resampled every frame. These are bounded source rules, not a statistical/runtime claim about perceived rarity.

Eight portable tests execute actual production mouth-crossing/pose/transit/planner algorithms, across viewport sizes, fully-entered bounds, exactly-once completion, reduced motion and spacing without a pass cap. Two additional tests drive the actual Combine view model's shared frame entry to check delayed star/fruit awards and actual fruit identity; **NOT RUN on Linux**. Full native-linked Linux tests remain distinct from iOS rendering/runtime acceptance.

Classification-mode bonus-star interaction/settlement parity remains unfinished and must be implemented with its accessibility controls; this batch verifies the active catch path only. Wind/rain/puddle/vine/branch physics and broader performance acceptance continue in subsequent source-order batches.

## Classification control parity follow-up

The classification path now presents the same rare standalone-star opportunities as untimed explicit catch/skip controls. Accepting fruit or stars queues the same shared entry/settlement state before applying awards or bad-fruit consequences. Declining a star has no penalty and does not fill the basket. Its basket uses the shared local pose calculation; reduced motion still shows a static settled pose. Duplicate star actions are guarded by clearing the presentation before transit begins.

The owned clock runs only while classification settlement is pending, stops after settlement, and resumes a pending transit after pause without a time jump. Switching control modes preserves earned counters and captured transits while replacing unselected/invisible presentations. Existing game-level and question-difficulty separation is unchanged. Added one portable local-pose regression plus two actual Combine view-model classification star regressions; the latter remain NOT RUN on Linux.
