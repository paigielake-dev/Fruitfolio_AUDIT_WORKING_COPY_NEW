# Translation input allocation budgets

The real translation service now checks foreign-language work before trimming, catalog lookup, paragraph splitting, scientific regex construction or task ownership. Admission accepts at most 1 MiB of UTF-8 source, 64 UTF-8 bytes for source-language identity, 1,024 protected literals, and 64 KiB of combined protected-literal UTF-8 bytes. Exceeding any budget throws the existing input-too-long error. No input is truncated or partially returned; existing display owners retain the original on failure. Same-language originals bypass inference and these allocation checks.

Two actual-service regressions reject six oversized source/metadata vectors before any protocol runtime invocation, assert no retained owner metadata, exercise the exact multibyte source/count/literal-byte boundaries, and confirm an oversized same-language original remains byte-identical without inference. Identity protocol output is not official model output. Smaller existing sharing bypasses remain supported. The model's own context/token bounds still apply after these service checks; admission does not promise a one-MiB passage will fit the model context.

Together with bounded task ownership this limits individual source/protection admission, not native model weights, all intermediate allocations, aggregate process RSS or caller-owned text. Real official-model/device memory, thermal performance, Apple fallback/retry/VoiceOver and native-language scientific/safety review remain unverified. Official weights/tokenizer remain unavailable. No whole memory, offline-inference or clinical requirement is certified.
